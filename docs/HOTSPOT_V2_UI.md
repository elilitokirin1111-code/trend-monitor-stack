# 热点情报中心 Frontend V2

## 1. 设计方向

Frontend V2 采用已确认的 D 融合方案：

- 桌面端以 Feedly/Brandwatch 一类的专业情报工作台为结构参考，强调高密度筛选、趋势阶段和数据质量。
- 事件详情采用 Ground News 一类的证据阅读逻辑，让聚合事件与各平台原始记录保持可追溯关系。
- 移动端采用横向平台状态条与事件卡片逻辑，保留快速浏览能力，但不牺牲 freshness/stale 标识。

上述产品只作为交互与信息架构参考，不复制其界面资产或源代码。

## 2. 产品信息架构

### 情报工作台

- 情报总览：平台健康、最新趋势运行、事件队列和证据抽屉。
- 热点发现：保留 HotPush 原有的平台热榜浏览能力。
- 趋势分析：保留现有排名趋势与统计能力，后续接入 EventCluster 历史序列。

### 数据与交付

- 数据源：Provider、平台和采集配置。
- 报告中心：日报、周报的生成、浏览与版本记录（下一 UI 批次）。
- 推送历史、推送配置：保留已有能力，后续统一到报告交付工作流。

### 系统管理

- 规则策略、采集调度、用户管理。
- 运行监控与告警中心（下一 UI 批次）。

## 3. UX Phase 1 已实现

- 重构全局应用外壳：产品品牌、分组导航、工作区状态、桌面与移动端响应式布局。
- 情报总览增加四平台采集状态条；点击平台直接筛选事件。
- 总览指标只读取 `/api/v1/hotspots/overview` 已有字段，不通过前端推测数据。
- 事件队列支持趋势阶段快捷筛选、标题搜索、平台/酒旅相关性/数据质量高级筛选。
- 支持紧凑列表和卡片浏览两种密度。
- 事件详情由居中弹窗改为右侧证据抽屉，分为“研判摘要”和“原始证据”两个栏目。
- 原始证据保留平台、Provider、榜单排名、freshness、观测时间、Raw ID、原平台和原始记录链接。
- 完整实现浅色/深色主题与 390px 移动端布局。
- 无生产采集数据时显示明确空态，不填充 sample/fake/mock 热点。

## 4. 当前真实 API 映射

| 前端区域 | API / 字段 |
| --- | --- |
| 平台状态条 | `GET /api/v1/hotspots/overview` → `platforms` |
| 总览指标 | `overview.event_count`、`trend_run`、`platforms[].status` |
| 事件队列 | `GET /api/v1/hotspots/events` |
| 事件筛选 | `q`、`platform`、`lifecycle`、`hospitality_relevance`、`data_quality` |
| 事件证据抽屉 | `GET /api/v1/hotspots/events/{event_id}` |
| 原始记录 | `evidence[].raw_item_url` |

## 5. 数据真实性约束

- `fresh`、`stale`、`failed`、`unavailable` 必须使用不同状态表达。
- 平台没有采集记录时显示“暂无数据”，不显示为健康或实时。
- AI 分类缺失时显示“未分类/未生成”，不在前端生成替代摘要。
- 没有历史时间序列 API 前，不绘制推测性趋势曲线。
- 当前指标均对应完整聚合结果或明确标注的当前查询结果。

## 6. 下一 UI Phase

1. 新增报告中心：日报/周报列表、详情、版本、生成、投递和重放。
2. 新增运行监控：Provider 成功率、stale 年龄、fallback 比率、失败投递和告警。
3. 为 EventCluster 增加历史序列 API 后，实现真实趋势曲线和生命周期时间线。
4. 将热点发现页升级为移动端内容运营流，并保持与聚合事件的跳转关系。
5. 补充组件级浏览器自动化测试和键盘焦点约束。
